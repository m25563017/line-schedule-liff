# ADR-0003：不讓機器人加入群組，改以 LIFF 分享與虛擬成員認領

> **關於本文件**：此決策在專案初期就已做出，本文件為事後補寫。作者當時的考量是「不想付費推播」與「不想讓使用者額外邀請機器人進群組」；其他選項為事後補充的評估。

## 背景與問題陳述

排時間需要兩件事：
1. **知道誰要參加**（成員名單）。
2. **通知大家**（邀請填寫、提醒未填、公告定案）。

一般的 LINE 機器人做法，是把機器人加入聊天群組，由機器人在群組內收集成員並推播訊息。這有兩個問題：

- 每個要使用的群組都得有人把機器人邀請進去，多一道手續。
- 機器人主動推播的訊息（Push Message）會計入官方帳號的訊息額度，超出免費額度需付費。

需要決定：成員名單與通知要怎麼處理，才能避開這兩個問題？

## 決策驅動因素

- 不想產生推播費用
- 使用者不需要額外邀請機器人進群組
- 主揪在網頁內就能完成建立與通知
- 朋友尚未使用過本服務時，也要能先被列入名單

## 考慮過的選項

- **A. 網頁內建立成員名單（含虛擬成員）＋邀請連結認領＋主揪以 LIFF 分享目標選擇器手動分享**
- **B. 機器人加入 LINE 群組，由機器人收集成員並在群組內推播**
- **C. 機器人以 Push Message 逐一通知每位成員**
- **D. 只提供複製文字，由主揪自行貼到聊天室**

## 決策結果

選擇 **A**。

- **名單**：主揪建立群組時，可先為還沒加入的朋友建立「虛擬成員」。朋友點邀請連結後「認領」該身分，系統把虛擬 id 換成其真實 LINE `userId`，並一併搬移已填的空檔資料。
- **通知**：提醒與定案卡片由主揪按按鈕，透過 `liff.shareTargetPicker` 選擇聊天室發出；不支援時改為複製文字（即選項 D 作為降級方案）。
- **機器人**：保留一個極簡的 Webhook，只在使用者加好友或傳訊息時，以回覆訊息（reply）回傳「打開排程」按鈕，不發出主動推播。

### 後果

**好處**

- 機器人不需要加入任何群組，使用者少一道設定
- 不使用 Push Message，不產生推播費用（回覆訊息的計費方式請以 LINE 官方說明為準）
- 虛擬成員讓主揪能在朋友還沒加入前就建好名單、代填空檔
- 邀請連結可貼到任何聊天室，不限特定群組

**代價與限制**

- **通知是手動的**：沒有活動前一天自動提醒，也無法對尚未填寫的成員自動催促
- **名單由主揪維護**：不會自動同步 LINE 群組的成員，需要主揪自己建立
- **認領機制依賴邀請連結只在自己的群組內流通**，後續可考慮加入主揪核可等機制
- **認領流程需跨多份文件更新**（群組文件與各活動文件），一致性保障（例如改用批次寫入或交易）列為改進項目
- `shareTargetPicker` 僅在 LIFF 環境且 LINE 版本支援時可用，否則降級為複製文字

### 驗證方式

在 LINE 內由主揪分享邀請卡片給朋友，朋友點連結認領虛擬成員，確認其空檔資料被正確搬移；在主揪頁面按提醒與定案按鈕，確認能選擇聊天室並送出卡片。

## 各選項的優缺點

### A. 網頁建名單＋認領＋LIFF 分享（採用）

- 好：免推播費用、機器人免進群組、名單與通知都在網頁內完成
- 壞：通知需手動；名單需手動維護；認領依賴邀請連結的流通範圍

### B. 機器人加入群組並推播

- 好：可在群組內自動互動，提醒可自動化
- 壞：每個群組都要邀請機器人；成員資訊的取得受 LINE 平台對群組成員資料的限制（細節以官方文件為準）；推播計入額度，可能產生費用

### C. 以 Push Message 逐一通知成員

- 好：可以個別、準時通知每個人，也能做排程提醒
- 壞：每則推播計入額度，成員多、提醒頻繁時成本上升；成員必須已與官方帳號為好友

### D. 只提供複製文字

- 好：最簡單，不依賴任何 LINE API
- 壞：體驗較差，主揪需手動貼上；本專案僅將它作為 A 的降級方案
